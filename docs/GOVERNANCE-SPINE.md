# 治理脊椎——工件本体与对账结构（Governance Spine）

> 本文档是 ming-skills 治理机制的本体地图：**map-not-ledger**。
> 它引导方向与判据，允许细节陈旧；工件家族表是人工审计视图，不是机查 SoT。
> 漂移容忍度：角色误标不可接受，行级滞后可接受。

## 1. 脊椎模型

本仓的治理工件按一个递归结构组织：

```
规范文档（spec，人可读意图）
  → 事实源（SoT，机可读声明）
    → 对账门（gate，声明<->工件比对）
      → 契约测试（test，门的第二形态意图）
```

每层都是上一层的对账物。递归**不靠"到最底层"终止**，靠 §4 的三种终止式之一。

## 2. 四角色

| 角色 | 定义 | 实例 |
|---|---|---|
| **SoT**（事实源） | 人故意编辑的机读声明，其他工件由其投影 | `registry.yaml`、`.hooksrc`、`INDEX.yaml`、SKILL.md frontmatter |
| **投影**（projection） | SoT 的纯函数产物，允许机器刷新 | `SKILL-INDEX.md` 条目、router manifest、`.githooks` shim、`## 目录` 节 |
| **对账门**（gate） | 声明<->工件比对器，输出差集 | `check-skill-index.mjs`、`gates/*.mjs`、`integrity.mjs` |
| **契约测试**（test） | 门正确性的意图第二形态 | `tests/unit`、`tests/contract` |

## 3. 三角判据

**一个门良构，当且仅当能显式点名它的两个顶点**（"拿 X 声明意图对账 Y 工件"）。

```
   独立工件 A ────── 独立工件 B
        \               /
         \   差集输出  /
          \           /
           对账器（门）
```

- **检测面对称**：对账器只能看见"不一致"，分不清错在哪边——registry 漏登记与 index 漏条目产出同样的差集报告。
- **修复面定向**：声明的权威侧决定"错了先修谁"；实际裁决仍是人（skill-index 一次差集同时修过两侧：index 漏登 + registry 乱码注释）。
- **第二顶点的住所**：另一个文件（registry<->index）/ 门代码内的声明规则表（secrets 模式表）/ 生成器确定性输出（manifest-freshness 重建比对）。
- 点不出第二顶点的门 = 意图藏在检查器里且未声明——脆弱且不可审，不造。

## 4. 三终止式

| 终止式 | 含义 | 实例 |
|---|---|---|
| **A. 人眼锚** | SoT 本身可信因为是故意的编辑 | `registry.yaml`、`.hooksrc`——门验证投影不验证它 |
| **B. 双 SoT 互证** | 两个独立维护工件互相对账即终结 | `.hooksrc`<->gate 模块（孤儿键检查）、INDEX<->distill 条目 |
| **C. 可执行契约** | 门正确性由测试锚定——测试人写一次后信任 | hook-engine 10 组断言 |

终止式 B 是大多数门的底层形态：**没有单一 SoT，只有互证的 SoT 对**——系统健康 = 互证网连通。

## 5. 周期维度

门的触发分两族，盲区在第二族：

| 触发 | 漂移源 | 覆盖 |
|---|---|---|
| **提交触发** | 工件因"我们的提交"漂移 | 现全部门 |
| **周期触发** | 工件因"世界自己变了"漂移（外源漂移） | `gate.<id>.cadence`/`chore.<id>.cadence` 引擎级键——last-run 时间戳存 `.git/hook-engine-state.json`，搭 stage 便车，TTL 封顶频率（已落地，首消费方 review-after） |

> 术语对照：周期触发门即 Ford《Building Evolutionary Architectures》的 **continual fitness function**（持续型适性函数——客观完整性评估的持续验证形态）；提交触发门对应 triggered 族。

外源漂移实例：reviewAfter 日期流逝、上游 repo 移动/404、死链、SCA 咨询库更新。便宜的检查（日期对账）可每次跑；贵的（网络请求）走长 cadence。

## 6. 四所有权带

生成物不是二元"生成/手写"，按所有权分带：

| 带 | 形态 | 实例 | 门的职责 |
|---|---|---|---|
| **全生成带** | 文件整体归生成器 | router manifest、sbom 产物 | 重建比对（freshness） |
| **节内嵌带** | 手主文件内嵌生成孤岛 | `## 目录` 节、shim 的 `node ...` 行 | 形状校验后定点重写 |
| **声明带** | SoT 本身 | `.hooksrc`、registry | 内部一致性对账（孤儿键） |
| **纯手写带** | 散文 | SKILL.md 正文、ADR | 只查派生视图不查内容 |

> 工业先例：节内嵌带与 K8s 对象 `spec`/`status` 分带同构——同一文件人写区（spec: registry 条目/layers/domains 表）与机写区（status: `checkCache` 由 update.ps1 写回）分带不越界。信任链保持 DAG+锚点（spec 是主），控制环保持闭环（写→观测→报告→修）。

**规则**：印记=所有权声明，误标=数据丢失（projen #638 先例）——节内嵌带的门必须先验证内容形状再改写，非生成形 warn-skip 不覆写。
**印记句式**（采纳 Go `Code generated ... DO NOT EDIT.` 正典的 md 变体）：

```html
<!-- Generated by <tool>; edit <source> instead. -->
```

## 7. 性能约束

- 引擎加载+自检族预算 **<500ms**（当前 ~100ms）
- 贵检查一律走 §5 cadence，不得在逐次路径上跑
- 测试深度归仓自选：`gate.impact-test.args` 透传，pre-commit 快档 / pre-push 全档的分配由仓配置决定

## 8. 规范性标记约定

规范文档条款可标注执行背书（WPT RFC 2119 惯例的本仓变体）：

| 标记 | 含义 |
|---|---|
| `【门:<id>】` | 该条款有可执行背书，由指定门执行 |
| `【约定】` | 人审约定，无机器检查 |
| `【不可查】` | 诚实边界——承认该条款机查不了（WPT `type:untestable` 对应物） |
