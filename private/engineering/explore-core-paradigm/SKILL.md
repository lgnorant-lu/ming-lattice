# Explore Core Paradigm — 跨场景发散探索元规则

发散是加宽候选面（找到没想到的选项），收敛是剪枝与承诺。与 review-core-paradigm 成对：本包管**承诺前**的候选生成，那边管**落定后**的消融评审。

## 1. 偏差前提（为何需要程序性发散）

- **人工蜂巢效应**：开放式生成上 LLM 双重坍缩——单模型自我重复 + 跨模型产出同质，且随代际恶化（diversity 逐年下降）。成因是偏好数据的 typicality bias：标注员偏爱熟悉文本 → 第一个答案系统性偏向**最典型**而非最优。
- **直觉不可靠**：「想到的第一个方案」与「最优方案」之间的间隙就是 hivemind 税——不发散就永远不知道付了多少。
- **对称性**：过度设计是收敛侧偏差（已由 review 对冲）；mode collapse 是发散侧偏差（本包对冲）。两者都是后训练产物，都需**程序性反制**而非态度要求。

## 2. 何时用 / 何时不用（任务分类先行）

**适用**：方案未定 / 开放问题 / 设计空间待探 / 第一答案「太典型」的直觉 / 决策点多路径不明。

**不适用（硬边界）**：
- **可验证单答案任务** → 走验证通道或 self-consistency（那边一致性投票才是对的工具）；
- **事实裁决** → 共识≠验证：聚合投票在事实任务上不优于单采样，「大家一致」不等于「是对的」；
- **已收敛任务的表演性发散**——发散有探索税，无场景的选项枚举是浪费。

## 3. 程序（升降模型）

发散的本质是**升降操作**：上升到抽象层看清空间，换轨，再降回实例层。

1. **上升**：把问题/当前方案抽象一层，显式暴露选项空间——这个问题的「分布/轴/策略维度」长什么样？（当前答案只是空间里的一个点）；
2. **换轨**：在抽象层移动（§4 算子菜单按场景选）；
3. **下降**：重新实例化成具体候选——每个候选须带可裁决断言（见 §6）；
4. **判据**：候选间 disagree → 回 2 续探；agree → 进承诺程序。

## 4. 发散算子（换轨方式，按场景选一或多）

| 算子 | 换轨机制 | 适用场景 |
|---|---|---|
| **Verbalized Sampling** | 要 k 个候选+各自概率，**从尾部采样**（p<0.10）而非 argmax | 通用首选——免训练、与温度正交、多样性 1.6-2.1× |
| **异策略路径** | 给并发生成者分配**不同推理策略**（不是 persona 皮），先显式产多条异质路径再评 | 多方案生成——破「固定心智集」，防辩论退化成多数投票 |
| **形态学矩阵** | 问题分解为轴×选项，重组生成新组合 | 设计空间可分解时（架构选型/产品形态） |
| **inversion / premortem** | 「它已经失败了，为什么」——承诺失败框架逼出具体因果链 | 承诺前的假设挖掘；对冲 sycophancy/乐观偏差（模型最抗拒的模式） |
| **ToT / beam + 回溯** | 节点采样多候选+自评+剪枝+可回溯 | 难搜索且中间态可评估时 |

SCAMPER/TRIZ 等大清单进 references 不进正文——模型先验已有，按 forge §7.1 不收。

## 5. 出口：候选集交给谁裁决

- 可验证任务 → 验证通道（测试/执行/形式检查）；
- 不可验证的取舍 → **review-core-paradigm**（消融剪枝）或**人**（意图上下文只在人手里）；
- **agree 只是承诺程序的门票，不是真理证书**——难任务上模型众数答案可能是集体坍缩（self-consistency backfire），一致性只能选「选项」，不能选「真相」。

## 6. 禁令

1. **[禁止] 把一致当真理**：agree→commit 的 commit 对象是候选排序，真相裁决走验证/评审/人；
2. **[禁止] 给可验证任务硬发散**：有标准答案时多样性是噪声不是财富；
3. **[禁止] 发散产物无断言**：每个候选必须带「怎么判它对错」——否则无法收敛，发散变成选项膨胀；
4. **[警告] 发散轮次须有限**：预算内收敛（探索税 vs 边际新候选收益），新候选趋同即停；
5. **[禁止] premortem 退化成负能量清单**：必须落回具体因果链与触发条件，「担心失败」不算 finding。

## 7. Compose

```
explore-core-paradigm（本包：承诺前候选生成）
+ review-core-paradigm（发散产候选 → 消融剪冗；互补对，非重叠）
+ depth-core-paradigm（候选 finding 的深度裁决——「这问题住第几层」走那边）
+ ming-experience-direction（设计域的备选案不混合制是该域专门化）
+ arch-core-paradigm（架构选型时的形态学矩阵落点）
```
