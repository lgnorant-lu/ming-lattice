# compiler-pipeline-paradigm — 编译器流水线九段契约元规则

> 「源文本→可执行物」轴在仓内已有多处独立消费：IV8 surface-codegen
> （IDL→IR→emit）、IDL 工具链（parse→merge→validate→IR）、
> ming-boundary（source→facts）、build-router-manifest（registry→投影）。
> 本包收九段的段间契约与取舍公理，不收具体语法/指令集。

## 1. 何时用 / 何时不用

- 适用：设计/评审编译器、转译器、代码生成器、DSL、IDL→IR→emit
  链、任何"结构化文本→另一种结构化产物"的多段管线；
  裁决"在哪一段做这件事"；做 JIT vs AOT、图着色 vs 线性扫描取舍
- 不适用：单段文本处理（正则替换/模板渲染不是流水线）；
  查询优化器（同构但归 DB 域）；纯解释器无 codegen 段

## 2. 九段契约表

每段收「输入→输出 / 核心不变量 / 该段的失败模式」。**段间只认
中间表示，不认上游实现**——这是整条链可测、可替换的根基。

| 段 | 输入→输出 | 核心不变量 | 典型失败模式 |
|---|---|---|---|
| 1. Lex（词法） | 字符流→token 流 | 最长匹配（maximal munch）；token 携带 source 位置 | 漏 lookahead 形态（Fortran 忽略空格：`DO 10 I = 1,5` 是循环、`DO10I = 1.5` 是赋值）；位置丢失使下游报错无锚 |
| 2. Parse（语法） | token 流→CST/AST | 文法无歧义（优先级经 factor/term 分层消解）；错误恢复可继续 | 悬空 else 二义性；panic-mode 恢复后产生毒化 AST |
| 3. Semantic（语义） | AST→已标注 AST | 作用域栈正确开合；类型/左右值/控制流校验全过 | 漏上下文约束（break 在循环外）；shadowing 把符号表查穿 |
| 4. AST-opt（高层优化） | AST→AST | "as-if" 原则——可观察行为不变 | 常量折叠改动 I/O 语义；宏展开破坏卫生性 |
| 5. IR 化 | AST→IR（三地址码/SSA） | 表达式树拍平；CFG 显式化；SSA 每变量单赋值+ϕ 节点 | ϕ 节点插错点；临时变量活性窗口算错 |
| 6. IR-opt（中端优化） | IR→IR | 数据流分析收敛（GVN/SCCP 不动点）；别名分析保守正确 | LICM 提出副作用；强度削弱破坏溢出语义；向量化前未做别名证明 |
| 7. Codegen（后端） | IR→目标指令 | 指令选择覆盖整棵表达式树；寄存器分配合法（无重叠生命周期同寄存器） | maximal munch 选错瓦片序列；spill 启发式把热变量踢出 |
| 8. Assemble | 指令→目标文件 | 两遍扫描/回填；重定位记录完整 | 符号未定义/重复在链接才爆——汇编期静默 |
| 9. Link/Load | 目标文件→可执行/已加载 | 符号解析闭合；PLT/GOT 延迟绑定正确；ABI 对齐 | DLL hell（版本漂移）；ASLR 下硬编码地址；CRT 初始化顺序错 |

## 3. 取舍模式册

### 3.1 质量 vs 编译延迟（寄存器分配原型）

寄存器分配是整条链最经典的取舍范式：

- **图着色**（AOT/热路径）：干扰图 K-着色 NP-Complete——质量好
  （少 spill）但编译时间不可控。GCC/Clang 与 HotSpot **C2** 用得起。
- **线性扫描**（JIT/冷路径）：活跃区间按开始时间排序贪心分配——
  质量略逊但快一个数量级。HotSpot **C1**、V8 TurboFan 走这条。
- **分层编译把两者变成共存而非二选一**：C1 快分配先上线、热点
  函数再被 C2 图着色重编——取舍轴其实是"每字节编译预算"，
  分层引擎按热度分桶花预算。
- **泛化判据**：运行时编译的延迟预算是硬约束（用户可感停顿），
  静态编译的质量上限是硬目标。**延迟预算决定算法天花板**——
  这不是"快算法 vs 好算法"，是"场景允许的成本上限"。

### 3.2 抽象机选型（指令发射的目标模型）

| 形态 | 代表 | 寄存器模型 | 取舍 |
|---|---|---|---|
| RISC（load-store） | ARM/RISC-V | 多而规整，三地址 | 发射简单、调度空间大；指令数多 |
| CISC | x86-64 | 少而有专用角色，两地址+寻址内嵌 | 单指令密度高（LEA 地址运算当乘法用）；寄存器压力大使分配更难 |
| 栈机 | JVM/WASM | 无寄存器，操作数栈求值 | 发射极简（无分配问题）；寄存器利用率损失交给运行时 JIT 补 |

判据：**栈机把寄存器分配问题推迟到 JIT 层**——编译器简单，运行时
还债。选栈机=承认"编译期不确定目标硬件"。

### 3.3 段间接口的硬约束

- **SSA 是单向门**：一旦转 SSA，下游所有优化都必须维护 ϕ 完整性；
  破坏 SSA 的 pass 必须重建或降级。IR 形态变更 = 契约主版本升级。
- **基本块是调度单元**：任何跨块重排必须通过数据流分析证明安全——
  裸重排指令序列不看依赖图 = 生成错误的乱序。
- **发射产物带锚点**：每段输出应携带上游可回溯位置（token 位置/
  IR 行号/机器码偏移），否则报错链断在"第 7 段说第 2 段错了"。

## 4. 优化段内部的次序纪律

IR-opt 各 pass 有隐含拓扑依赖，乱序即亏：

```
SCCP(含常量折叠) -> GVN -> LICM -> 强度削弱 -> 向量化
       ^-- 别名/纯度分析（前置供给，全部被消费）--^
```

- 别名分析是**前置供给 pass**——向量化/LICM 都消费它的结论；
  别名分析保守（"可能别名"）= 下游集体放弃优化（保守方向正确，
  但虚警是优化天敌）。
- PGO/LTO 是横切增强而非新段——它们重跑 6 段但带真实数据；
  接入点是 IR 层注释（branch likelihood），不是独立通道。

## 5. 禁令

1. **[禁止] 段间绕过 IR**：第 N 段直接读第 N-2 段的私有结构 =
   隐式耦合，中间表示换实现时全线崩。
2. **[禁止] 无位置锚的报错**：任何段的诊断必须带源头位置链，
   "emit 阶段报语法错误"说明位置信息在某段丢了。
3. **[禁止] AST 级跑重优化**：AST 表达的是语法结构不是数据流——
   在 AST 上做强数据流优化（如别名分析）是段位错配。
4. **[禁止] JIT 上图着色**（除非分层编译证明预算够）：编译延迟
   进用户可感路径时，编译器自身的时间复杂度就是性能缺陷。
5. **[禁止] ABI 违约静默**：跨段/跨编译单元的调用约定必须显式
   握手——栈对齐错不在调用点爆炸，在深处随机崩（见
   contract-core-paradigm §3.5）。
