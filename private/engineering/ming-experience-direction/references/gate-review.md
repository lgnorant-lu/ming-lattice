# 决策门禁、OQ 台账与备选案协议

## 1. 六门判定细则

蓝图（收束文档）进入实现前逐门过审，每门写一句判据 + PASS/FAIL 结论：

| 门 | 判定问题 | 常见 FAIL 模式 |
|---|---|---|
| 追溯门 | 每处决策能否指到宪法某条原则编号？ | "感觉高级"无原则依据；引用了不存在的原则 |
| 情绪门 | 整体气质命中哲学层目标情绪？有无非目标元素混入？ | 目标"肃穆可信"却混入弹跳动画、消费级圆角卡片 |
| 克制门 | 密度/亮度/元素数守住留白预算？ | 全屏高亮、处处发光——克制失守等于没有重点 |
| 解释门 | 每个视觉元素能答出"它代表什么语义实体/状态"？ | 纯装饰粒子、说不出语义的发光边框 |
| 降级门 | reduced-motion、低端设备、无 GPU 路径是否设计过？ | "直接关掉动效"——信息随之丢失，是砍掉不是降级 |
| 可行门 | 媒介配比、资产体积、首载在性能预算内？ | WebGL 场景阻塞首屏；无预算数字的"应该够快" |

记录格式（写进蓝图文档）：

```text
[PASS] 追溯门：<判据一句，引宪法条号>
[PASS] 情绪门：<命中的目标情绪词 + 排除的非目标元素>
...
自审结论：Pass —— 允许进入实现 / Fail —— 回退到第 N 层返修
```

门集合可按项目裁剪（如纯静态页免降级门），但**不可免审**——门禁存在的意义是把"审过了"从口头印象变成文档事实。

## 2. OQ Register 协议

```text
| ID | 问题 | 当前状态 | 备注 |
状态集合：open / hypothesis / accepted / rejected / deferred / blocked
```

- **open**：已知未决，无工作值；
- **hypothesis**：有工作假设值，备注写明"工作假设，非事实"；设计可基于它推进但文档引用时必须带假设标记；
- **accepted**：确认为事实，可当依据引用；
- **rejected**：考虑过且否决——备注留否决理由，防同一问题反复复活；
- **deferred**：有意推迟（写触发条件）；**blocked**：被外部因素卡住（写等谁）。

分组建议：A 需求事实与边界 / B 世界观与产品人格 / C 能力与叙事 / D 媒介与技术。每组的 hypothesis 数量是该层设计风险的直接度量——B 组一片 hypothesis 时不宜进语法层。

## 3. 备选案协议

多案竞选流程：

1. 每案一页：总命题 + 故事弧 + 与宪法的契合点；
2. 选主案的理由必须写成"为什么它最合宪法与实例化基线"，不是"它最酷"；
3. 落选案**封存不删除**——保留档，标注"备选，不与主案混合"；
4. 封存案禁止混入主案的领域对象、语义词表、证明逻辑；
5. 唯一复活路径：主案被正式否决并记录理由——不是"做一半觉得另一个好"。

## 4. Deliberation Record 协议

- 性质 informative（证据档案），不是 normative（规范）——引用它说明"为什么这么定"，不拿它当约束条文；
- 记推理不记流水：原始信号的信息量评估、概念澄清的演化、被排除的误读；
- 价值在防"只见结论不见推理"——后续修订者能判断原则前提是否仍成立。

## 5. 评审相位：三类评审不可混开

外部先例（Storyflow/Nielsen crit 协议）确认：**把三类评审混在一个会议/一个检查点，是设计评审最大的浪费源**——拿执行稿重新开庭方向、或拿草图审工艺，都是结构性失败而非态度问题。

| 相位 | 问什么 | 发生在 | 规范 | 失败模式 |
|---|---|---|---|---|
| **发散评审**（direction review） | 方向对吗？还有别的路径吗？ | 概念竞选期（02 叙事、03 概念） | 多案上桌即成功；"what if" 是合法贡献；**禁止挑工艺刺** | 拿抛光稿上发散评审——精修外观暗示已定案，扼杀发散 |
| **工艺评审**（craft review） | 这层语法自洽吗？词表归得进吗？边界守住了吗？ | 各 pulse 层出稿时（04-09） | 只审本层语义与边界；"是什么"已锁，只问"写对没有" | 重开方向讨论——该层上游已定，重开=翻案 |
| **决策评审**（decision review） | 能进实现吗？ | 蓝图收束点（六门过审） | 收敛，只答过/不过；记录决定与属主 | 产出讨论不产出决定——评审开完没有 PASS/FAIL 结论等于没开 |

配套纪律：

- **评审邀请先声明相位**——"今天是发散还是决策"不写明，与会者会自带不同剧本；
- **pre-read 先行**：问题、约束、要回答的具体问题提前给——Nielsen crit 协议同款；
- **反馈只对声明的问题**——超出当次相位的意见记入 OQ 台账，不当场展开；
- **决定与属主当场落档**——评审产出不写进文档 = 评审没发生过。
